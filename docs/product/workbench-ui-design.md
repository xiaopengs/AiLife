# 小红书 Skill 赛道运营工作台：界面设计方案

**状态：** 已确认，待实现  
**日期：** 2026-08-28  
**作者：** Manus AI

## 1. 需求解读

本次新增需求是在现有“小红书 Skill 赛道运营平台”首版范围内，设计一套高信息密度、专业且易浏览的运营工作台界面。用户提供的参考图仅作为布局密度、内容协同性与轻盈质感的方向参考；最终界面不得复刻其品牌、人物、文案、封面或视觉资产，而应以项目自身的「小红书 Skill 赛道运营」定位建立原创设计语言。

界面首屏需要把运营人员的日常优先级集中呈现：本周的选题与待办、内容生产中的草稿与审核、即将发布的排期，以及从曝光到涨粉的复盘指标。首版不连接小红书账号，也不进行自动发布；一切发布相关功能仅表达人工协同、检查与登记的工作流。

| 设计目标 | 界面响应 |
|---|---|
| 运营总览 | 在首屏展示核心运营指标、趋势与阶段漏斗，快速识别本周的工作压力。 |
| 内容闭环 | 用紧凑的内容看板把选题、创作、审核、待发布连接为明确状态。 |
| 人工发布协同 | 将发布前检查、排期与人工发布登记显式放入右侧协同区。 |
| 运营复盘 | 以可读的趋势图、标签化洞察和表现较好的内容卡片展示复盘线索。 |
| 专业体验 | 固定侧栏、分组导航、柔和卡片与分层数据视图保持长时间使用的舒适性。 |

## 2. 信息架构

工作台采用“固定侧栏 + 顶部情境栏 + 主任务区 + 协同侧栏”的布局。左侧提供跨模块导航和当前项目集合；中间成为本周运营决策与内容生产的主要区域；右侧保留快速待办、人工发布检查和 AI 运营建议，使用户不离开当前页面也能完成必要协同。

| 区域 | 承载内容 | 主要目的 |
|---|---|---|
| 左侧导航 | 运营总览、内容库、创作工作流、内容日历、发布协同、运营复盘及项目集合 | 提供稳定的产品骨架与清晰跳转路径。 |
| 顶部情境栏 | 页面标题、当前周期、搜索入口、通知和用户菜单 | 传递当前上下文，减少切换成本。 |
| 指标带 | 选题储备、生产中、待审核、待发布与互动增量 | 在一屏内明确运营节奏与优先事项。 |
| 中央工作区 | 周计划、内容管线、表现趋势和最近内容 | 聚焦运营工作流和高价值信息。 |
| 右侧协同栏 | 今日待办、发布前检查、AI 运营建议 | 形成行动闭环，避免指标仅停留在展示层。 |

## 3. 原创视觉方向

整体命名为 **「赤陶编辑部」**。它避免直接使用常见的科技蓝或大面积渐变，而以暖白色工作底板、墨色导航、番茄红的主动色和鼠尾草绿的增长色建立内容运营的编辑感。深色侧栏类似编辑部的工具柜，中央卡片像铺陈在桌面的选题单与稿件，数据图表采用细线与留白保证可读性。

| 视觉层 | 设计决定 |
|---|---|
| 色彩 | 背景以暖灰白为主；品牌主动色采用番茄红；成功与增长采用低饱和鼠尾草绿；分析强调采用柔和琥珀色。 |
| 字体 | 使用系统中文无衬线字体，标题通过字重与紧密字距建立编辑感，而非依赖外部字体。 |
| 形状 | 使用 14–20px 圆角和极浅阴影；卡片边界可见但不形成厚重的“卡片墙”。 |
| 图表 | 轻线条折线、细网格、圆点锚记和内嵌标注，保证趋势优先于装饰。 |
| 图像 | 首版采用抽象渐变、纹理图形和内容类型图标作为封面，避免使用未经授权的人像、平台素材或 AI 图片。 |

## 4. 首屏内容与交互

首屏默认展示运营总览。指标卡、内容管线和最近内容均使用静态的示例运营数据，以便先完成视觉与交互验证。导航项在当前版本会作为前端原型入口：切换时更新选中状态并以提示反馈尚未实现的独立页面。搜索、通知、邀请协作者、导出周报等按钮同样保留明确的非破坏性反馈。

内容管线中的内容行能表达“选题、脚本、审核、排期”四个阶段；用户可通过主界面的「新建内容」按钮打开创作提示。右侧“发布前检查”则清晰提示：核对封面、检查标签、确认排期和记录人工发布结果。该设计不会暗示或执行任何直接操作小红书账号的能力。

## 5. 响应式与验收标准

桌面端优先呈现完整三栏工作面，1200px 以下将协同栏下移，960px 以下隐藏部分次级数据，移动端切换为可展开导航与纵向卡片流。所有可操作元素保留可见焦点状态、语义化按钮和键盘可达性；状态切换与提示反馈的过渡时间保持短促，且对“减少动态效果”偏好降级。

完成实现后，验收应确认首屏在常见桌面宽度下结构完整、视觉层级清晰、图表不依赖外部网络资源、导航与关键按钮都有可理解的反馈、界面不涉及账号自动发布，且 TypeScript 检查与生产构建均可通过。

## 6. 变更控制

后续若修改模块范围、品牌语言、发布能力或数据持久化方式，应先更新本文档与 `CHANGELOG.md`，再实施代码变更，并将每个逻辑变更提交到仓库。
