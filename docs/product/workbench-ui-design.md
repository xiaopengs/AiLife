# 小红书 Skill 赛道运营工作台：界面设计方案

**状态：** 已确认，基于真实运营功能进行界面升级
**日期：** 2026-08-28  
**作者：** Manus AI

## 1. 需求解读

本次新增需求是在现有“小红书 Skill 赛道运营平台”首版范围内，设计一套高信息密度、专业且易浏览的运营工作台界面。用户提供的参考图仅作为布局密度、内容协同性与轻盈质感的方向参考；最终界面不得复刻其品牌、人物、文案、封面或视觉资产，而应以项目自身的「小红书 Skill 赛道运营」定位建立原创设计语言。

界面首屏需要把运营人员的日常优先级集中呈现：本周的选题与待办、内容生产中的草稿与审核、即将发布的排期，以及从曝光到涨粉的复盘指标。首版不连接小红书账号，也不进行自动发布；一切发布相关功能仅表达人工协同、检查与登记的工作流。

| 设计目标 | 界面响应 |
|---|---|
| 运营总览 | 在首屏展示核心运营指标、趋势与阶段漏斗，快速识别本周的工作压力。 |
| 内容闭环 | 用紧凑的内容看板把选题、创作、审核、待发布连接为明确状态。 |
| 人工发布协同 | 将发布前检查、排期与人工发布登记显式放入右侧协同区。 |
| 运营复盘 | 以可读的趋势图、标签化洞察和表现较好的内容卡片展示复盘线索。 |
| 专业体验 | 固定侧栏、分组导航、柔和卡片与分层数据视图保持长时间使用的舒适性。 |

## 2. 信息架构

工作台采用“固定侧栏 + 顶部情境栏 + 主任务区 + 协同侧栏”的布局。左侧提供跨模块导航和当前项目集合；中间成为本周运营决策与内容生产的主要区域；右侧保留快速待办、人工发布检查和 AI 运营建议，使用户不离开当前页面也能完成必要协同。

| 区域 | 承载内容 | 主要目的 |
|---|---|---|
| 左侧导航 | 运营总览、内容库、创作工作流、内容日历、发布协同、运营复盘及项目集合 | 提供稳定的产品骨架与清晰跳转路径。 |
| 顶部情境栏 | 页面标题、当前周期、搜索入口、通知和用户菜单 | 传递当前上下文，减少切换成本。 |
| 指标带 | 选题储备、生产中、待审核、待发布与互动增量 | 在一屏内明确运营节奏与优先事项。 |
| 中央工作区 | 周计划、内容管线、表现趋势和最近内容 | 聚焦运营工作流和高价值信息。 |
| 右侧协同栏 | 今日待办、发布前检查、AI 运营建议 | 形成行动闭环，避免指标仅停留在展示层。 |

## 3. 原创视觉方向

整体命名为 **「赤陶编辑部」**。它避免直接使用常见的科技蓝或大面积渐变，而以暖白色工作底板、墨色导航、番茄红的主动色和鼠尾草绿的增长色建立内容运营的编辑感。深色侧栏类似编辑部的工具柜，中央卡片像铺陈在桌面的选题单与稿件，数据图表采用细线与留白保证可读性。

| 视觉层 | 设计决定 |
|---|---|
| 色彩 | 背景以暖灰白为主；品牌主动色采用番茄红；成功与增长采用低饱和鼠尾草绿；分析强调采用柔和琥珀色。 |
| 字体 | 使用系统中文无衬线字体，标题通过字重与紧密字距建立编辑感，而非依赖外部字体。 |
| 形状 | 使用 14–20px 圆角和极浅阴影；卡片边界可见但不形成厚重的“卡片墙”。 |
| 图表 | 轻线条折线、细网格、圆点锚记和内嵌标注，保证趋势优先于装饰。 |
| 图像 | 首版采用抽象渐变、纹理图形和内容类型图标作为封面，避免使用未经授权的人像、平台素材或 AI 图片。 |

## 4. 首屏内容与交互

首屏默认展示运营总览。经协作版本核查，项目已具备登录隔离、内容实体、运营总览聚合、内容库、生产流、发布日历与复盘五个真实业务模块。因此，界面升级必须直接消费既有的 `content.overview` 数据，而不以静态示例替代真实指标。指标带将映射选题储备、待审核、待发布、累计涨粉与内容阶段；“需要关注”列表复用已有的待处理内容；复盘区仅展示已记录的曝光、互动、互动率与涨粉数据。

全局侧栏保留既有路由和认证逻辑，但更新为深色编辑部工具柜：顶部增加品牌识别和“新建选题”直达入口，主导航保持运营总览、内容库、内容生产、发布日历与运营复盘五个工作区。总览主区域采用“情境标题—指标带—阶段分布与待办—复盘与人工发布协同”的高密度布局。所有按钮均跳转至已实现的业务页面，或保持对当前真实操作流的明确引导，不增加仅用于演示的虚构数据或伪交互。

发布前检查、排期和人工发布结果登记继续留在既有发布日历模块中。工作台只突出待发布数量与流程入口，明确说明平台不会读取或直接操作小红书账号。

## 5. 响应式与验收标准

桌面端优先呈现完整侧栏与双列总览主区，1200px 以下将右侧复盘与协同卡转为下方内容区，960px 以下隐藏侧栏的次级文案，移动端继续使用现有可展开导航与纵向卡片流。所有可操作元素保留可见焦点状态、语义化链接或按钮和键盘可达性；状态变化的过渡保持短促，且对“减少动态效果”偏好降级。

完成实现后，验收应确认首屏在常见桌面宽度下结构完整、视觉层级清晰，所有指标来自已登录用户的真实聚合数据，阶段分布与待关注内容均保持既有逻辑，关键入口仍可达对应路由，界面不涉及账号自动发布，且 TypeScript 检查、现有测试与生产构建均可通过。

## 6. 变更控制

后续若修改模块范围、品牌语言、发布能力或数据持久化方式，应先更新本文档与 `CHANGELOG.md`，再实施代码变更，并将每个逻辑变更提交到仓库。

## 7. 协作版本核查与改造取舍

在方案形成后，远端协作版本新增了完整的受保护业务实现。本次不再引入覆盖真实数据的静态原型，而是以视觉重构方式提升已经上线的运营总览：保留所有既有 tRPC 查询、用户隔离、内容状态、路由跳转和人工发布边界，只调整首页的信息编排与共享工作台外壳。这个取舍避免因展示层升级造成内容创建、审核、排期、发布登记或运营复盘能力退化。


## 8. 验证记录

2026-08-28 已在本地浏览器检查无有效登录会话时的渲染结果。页面先完成加载，随后正确显示既有的安全登录入口，包含“让每一次创作都有清晰的去处”的说明与“进入工作台”按钮；未向匿名会话展示运营指标、内容条目或演示数据。该行为符合真实数据按登录身份隔离的既有边界。

视觉升级涉及的首页数据读取、阶段分布、待办跳转和复盘入口均保留既有查询与路由实现。由于当前本地 OAuth 环境未配置可用的登录服务，无法在匿名浏览器会话中完成登录后的真实数据视觉验收；该项目待办保留“已登录工作台验证”作为后续人工验收项。工程层面的类型检查和生产构建已成功通过。
