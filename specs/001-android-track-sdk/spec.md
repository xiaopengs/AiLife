# 001-android-track-sdk · 规格说明书

## 基本信息
- **Feature**: Android 端侧埋点 SDK + 端侧数据中台（系统数据服务）：采集 → 跨进程 → 端侧处理存储 → 上报云侧
- **Branch**: `qoder/general-session-q2dmus`
- **规格 ID**: `001-android-track-sdk`
- **技术栈约束**: 全部在 Android 端侧实现；SDK 与数据中台服务均为 Java 8（minSdk 21）

## 概念与范围界定（重要）
- **数据中台 = 端侧的系统数据服务**：运行在设备的数据平台进程内的常驻服务，负责统一接收各业务进程埋点、端侧处理（校验/去重/合并/采样/补齐）、端侧存储、向云侧上报，并对端侧消费方（看板/智能体）提供本地查询
- **云侧**：接收网关、配置中心、数据服务仅作为上报目标与接口约定出现，**不属于本方案实现范围**
- **通道**：业务进程内存 → 业务进程磁盘兜底 → Binder IPC → 端侧数据中台处理 → 端侧统一存储 → 云侧上报 的完整端内链路

## 术语表
| 术语 | 定义 |
| --- | --- |
| 点位 / 埋点（Event） | 一次带业务语义的行为记录：事件 ID、时间戳、属性、公共属性快照 |
| 数据平台进程 | 设备上承载数据中台能力的常驻进程，宿主 DataProvider、端侧处理引擎、统一存储、上报调度与自监控 |
| DataProvider | 系统数据服务模块：以 `ContentProvider` 形式暴露的端侧数据中台统一接入点（Binder） |
| 端侧数据中台 | 数据平台进程内各服务（接入/处理/存储/上报/监控/查询）的逻辑总称 |
| 通道 | 见「概念与范围界定」；本规格的稳定性设计对象 |

## 用户故事与验收标准

### US1 — 业务接入埋点
**作为** 业务开发者，**我要** 通过简洁的 Java API 记录埋点，**以便** 不理解通道细节也能完成数据采集。

**验收标准**
- **WHEN** 业务调用 `AilifeTrack.init(Context, TrackConfig)` THEN 50ms 内返回（P95），通道连接异步进行，**且** 不阻塞主线程、不抛出未捕获异常
- **WHEN** 业务调用 `track(eventId, properties)` THEN 2ms 内返回（P95），事件入内存队列并落通道本地兜底库，**且** API 线程安全，可任意线程调用
- **WHEN** 业务调用 `trackList(events)` THEN 单次至多 200 条，超出自动分批
- **WHEN** 未 `init` 或初始化失败时调用 `track` THEN 事件写入进程内持久化恢复队列，初始化成功后自动补传，不丢失
- **WHEN** 业务未声明某权限 THEN SDK 不代业务申请权限，对应公共属性采集自动降级

### US2 — 跨进程传输（业务进程 → 端侧数据中台）
**作为** 端侧数据中台，**我要** 通过 DataProvider 以 Binder 进程间通信集中接收各业务进程的事件，**以便** 统一协议、鉴权、控量与端侧处理，业务进程不直接访问网络。

**验收标准**
- **WHEN** 业务进程调用 `insert()` THEN 事件以 protobuf + gzip 编码批量传输，单次 IPC ≤ 256KB（压缩后）
- **结果码契约**：`insert()` 返回 `RESULT_SUCCEEDED / RESULT_THROTTLED / RESULT_RETRY_LATER / RESULT_INVALID`，调用方按码处置：成功→删本地；THROTTLED→退避重试；RETRY_LATER→保留待下次窗口；INVALID→落损坏区，不重传并计数
- **WHEN** 数据平台进程被杀 THEN SDK 捕获 `DEAD_OBJECT`，本地保留数据，指数退避重连（1s 起 ×2，上限 30s，±20% 抖动），服务恢复后自动续传并回到实时模式
- **WHEN** 数据平台进程升级中 THEN `insert()` 返回 `RESULT_RETRY_LATER`，业务进程本地保留，升级完成自动续传
- **WHEN** 协议 major 版本不兼容 THEN DataProvider 拒绝并返回 `RESULT_INVALID`，同时记兼容性监控；minor 版本向后兼容
- **WHEN** 调用方签名校验或自定义权限校验不通过 THEN 拒绝并计数，记入端侧安全事件

### US3 — 端侧处理与存储（数据中台核心）
**作为** 端侧数据中台，**我要** 对接入事件做统一处理与本地存储，**以便** 形成可信的端侧数据资产并支撑上报与本地消费。

**验收标准**
- **处理流水线**：接入后依次完成 校验（schema/枚举/长度）→ dedupKey 去重（90s 窗口，可配）→ 合并窗口（同 key 计数聚合）→ 采样（按点位采样率）→ 公共属性补齐 → 会话生成；各阶段故障互不传染
- **WHEN** 处理任一阶段异常 THEN 该事件进入隔离区并计数，不影响后续事件处理
- **端侧统一存储**：Room 按天分区：明细表、会话表、用户属性表、指标表；写入单事务，插入处理 P95 ≤ 10ms
- **存储治理**：TTL 3 天（可配 1–7 天）；磁盘配额 20MB（可配 5–50MB），满时按「最新优先」淨汰最旧分区并计数；上报确认后才可清除对应数据（先落盘后传输）
- **WHEN** 本地查询 `queryTrack()` THEN 授权消费方（端侧看板/智能体）可只读查询明细/会话/指标，查询不阻塞写入

### US4 — 端侧实时上报云侧
**作为** 端侧数据中台，**我要** 将端侧数据按策略实时批量上报云侧，**以便** 云侧及时获得数据且不耗费过多设备资源。

**验收标准**
- **count/size/time 三维触发**：合并窗口 5s 到期、批满 50 条、累计 256KB（压缩后）任一满足即触发上报
- **网络策略**：默认 Wi-Fi 立即报、蜂窝按阈值（可配）延迟批量报、无网络滞留待报队列；网络恢复立即续传
- **WHEN** 上报失败 THEN 指数退避重试 30s/1m/5m/30m 共 4 次，失败数据回队列头；断点续传（分片确认后清除）
- **WHEN** 云端返回 401/403 THEN 停止上报并告警（端侧记录）；429 → 按 `Retry-After` 退避；5xx/网络错误 → 指数退避
- **端侧流控**：令牌桶默认 1000 ev/s、桶深 1000；超出进入待报队列而非丢弃；参数可由云端配置动态下发（100–2000 ev/s）
- **分级降级**：通道健康度 < 0.6 时进入「仅缓存模式」：采集与端侧处理照常、上报暂停；恢复 ≥ 0.8 且持续 10min 后渐进放量（1/4 → 1/2 → 全量，每级稳定 5min）
- **WHEN** 设备/用户行使退出权（`optOut`） THEN 立即停止采集与上报、清空待报数据、状态持久化；`optIn` 后重新采集
- **实时性界定**：事件从进入到端侧统一存储 ≤ 10s（P95）；上报时延目标：Wi-Fi 下 ≤ 30s（P95）

### US5 — 端侧自监控与稳定性
**作为** 端侧稳定性负责人，**我要** 数据中台与通道的异常都被分类处置、降级和计数，**以便** 数据完整性可审计、不因通道故障影响业务进程。

**验收标准**
- **WHEN** 单条事件压缩后 > 256KB THEN 拆分重编码；> 1MB 判定为业务异常数据，丢弃并计丢弃计数，保护通道
- **WHEN** 同一 `dedupKey` 事件 90s 窗口内重复到达 THEN 幂等去重，仅计一次（可配窗口）
- **WHEN** IPC 传输异常（`DEAD_OBJECT` / `RuntimeException` / 8s 超时） THEN 保留本地、退避重连；insert 是轻操作，超时视为中台异常信号
- **WHEN** 业务进程被杀 THEN 事件已先落通道本地兜底库，进程重启后续传
- **WHEN** 数据平台进程被杀 THEN 业务进程继续采集落本地，服务恢复后分批补传
- **WHEN** SDK 自身发生未捕获异常 THEN 拦截器捕获后隔离故障模块，业务进程不受影响；SDK 崩溃率 0（不产生业务进程新增崩溃）
- **WHEN** 数据平台进程被杀后依赖系统/平台拉活恢复 THEN SDK 侧只负责退避重连，不做进程保活
- **自监控指标**：丢弃率、上报成功率、端侧延迟、协议拒绝率、存储水位、健康度；随批量上报云侧，亦可经 `queryTrack()` 本地查询

### US6 — 不丢数据总原则
**双进程均「先落盘后传输」**：事件先落业务进程通道兜底库与端侧统一存储，传输/上报确认成功才删除；配合 dedupKey 幂等去重，实现端内全链路「至少一次 + 幂等去重」。

## 边界情况（Edge Cases）
| # | 场景 | 处置 |
| --- | --- | --- |
| E1 | 事件属性含非法值（NaN/超长字符串） | 入队前校验：非法值剔除属性并计数；事件主体保留 |
| E2 | 云端配置拉取失败 | 沿用上次有效端侧配置，5min 后重试 |
| E3 | 设备磁盘满（< 10MB 可用） | 磁盘队列写入失败转降级内存缓冲（512KB 有界，满则丢最旧+计数），恢复后回灌 |
| E4 | 多进程并发写入 DataProvider（≥ 3 个业务进程） | Provider 内部串行化（单写线程 + 锁），插入 P95 ≤ 10ms |
| E4b | 同一进程高并发调用 track() | 内存队列加锁，单消费者批量出队 |
| E5 | 客户端时钟偏移 | 事件携带 SDK 时间戳 + 中台接收时间戳双时间戳，双轨计算 |
| E6 | 重复上报（重传后云端已收） | 云端按 dedupKey 幂等去重（接口约定）；端侧 90s 窗口去重 |
| E7 | 协议字段新增（minor 升级） | proto 未知字段保留；旧客户端收到新字段忽略 |
| E8 | 用户提供非法 config（非法 URL/负数阈值） | 初始化时校验，非法值回退默认值并计数 |
| E8b | 云端下发非法配置 | 校验后拒绝并沿用上次有效配置 |
| E9 | 事件 ID 未知 | 收录并计数（未知点位计数上报，用于发现脏数据） |
| E10 | 队列出现超 TTL（3 天）数据 | 上报前过滤丢弃并计数 |
| E11 | 云端返回格式错误响应 | 截留原始响应采样存证，按 5xx 处置 |
| E12 | 用户频繁 optOut/optIn 切换 | 状态持久化 + 防抖（10s 内重复切换合并），清空动作幂等 |

## 功能边界（Non-Goals / Out of Scope）
- 云端接收网关、配置中心、云端数据服务只做接口约定，不在本期实现范围
- 不做 UI 埋点可视化（圈选）与 A/B 实验平台，本期只提供端侧采集与传输能力
- 不做跨设备数据同步与用户画像计算
- SDK 与数据中台不做进程保活（拉活由系统/平台策略负责），只负责退避重连
- 端侧查询的下游消费方（看板/智能体）仅为契约方，其内部实现不在本规格范围
