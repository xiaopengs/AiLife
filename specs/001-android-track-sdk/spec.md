# 001-android-track-sdk · 规格说明书

## 基本信息
- **Feature**: Android 端侧埋点 SDK（业务进程采集 + DataProvider 跨进程通道 + 数据中台接收处理）
- **Branch**: `qoder/general-session-q2dmus`
- **规格 ID**: `001-android-track-sdk`
- **技术栈约束**: Java 技术栈（SDK minSdk 21+ / Java 8；服务端 Java 17 + Spring Boot 3）

## 术语表
| 术语 | 定义 |
| --- | --- |
| 点位 / 埋点（Event） | 一次带业务语义的用户行为或系统事件记录：事件 ID、时间戳、属性、公共属性快照 |
| 数据平台进程 | 设备上承载数据平台能力的常驻进程，宿主 DataProvider 与上报客户端，与业务进程通过 Binder 通信 |
| DataProvider | SDK 的「系统数据服务模块」，以 `ContentProvider` 形式运行在数据平台进程内，负责接收、校验、缓冲与上报 |
| 通道 | 事件从业务进程内存到数据中台落库的完整链路：采集 → 队列 → IPC → 平台缓冲 → 上报 → 服务端 |

## 用户故事与验收标准

### US1 — 业务接入埋点
**作为** 业务开发者，**我要** 通过简洁的 Java API 记录埋点，**以便** 不理解通道细节也能完成数据采集。

**验收标准**
- **WHEN** 业务调用 `AilifeTrack.init(Context, TrackConfig)` THEN 初始化 50ms 内返回（P95），实际通道连接异步进行，**且** 不阻塞主线程、不抛出未捕获异常
- **WHEN** 业务调用 `track(eventId, properties)` THEN 2ms 内返回（P95），事件入内存队列，**且** API 线程安全，可任意线程调用
- **WHEN** 业务调用 `trackList(events)` THEN 单次至多 200 条，超出自动分批
- **WHEN** 未 `init` 或初始化失败时调用 `track` THEN 事件写入进程内持久化恢复队列，初始化成功后自动补传，不丢失
- **WHEN** 业务未声明某权限（如精简的设备信息权限）THEN SDK 不代业务申请权限，对应公共属性采集自动降级

### US2 — 跨进程传输
**作为** 数据平台，**我要** 通过 DataProvider 以进程间通信方式集中接收各业务进程的事件，**以便** 统一协议、鉴权、控量与上报，业务进程不直接访问网络。

**验收标准**
- **WHEN** 业务进程调用 `insert()` THEN 事件以 protobuf + gzip 编码批量传输，单次 IPC ≤ 256KB（压缩后）
- **结果码契约**：`insert()` 返回 `RESULT_SUCCEEDED / RESULT_THROTTLED / RESULT_RETRY_LATER / RESULT_INVALID`，调用方按码处置：成功→删本地；THROTTLED→退避重试；RETRY_LATER→保留待下次窗口；INVALID→落损坏区，不重传并计数
- **WHEN** 数据平台进程被杀 THEN SDK 捕获 `DEAD_OBJECT` / `DeadObjectException`，本地保留数据，指数退避重连（1s 起 ×2，上限 30s，±20% 抖动），恢复后自动恢复实时模式
- **WHEN** 数据平台进程升级中 THEN `insert()` 返回 `RESULT_RETRY_LATER`，业务进程本地保留，升级完成自动续传
- **WHEN** 协议 major 版本不兼容 THEN DataProvider 拒绝并返回 `RESULT_INVALID`，同时上报兼容性监控；minor 版本向后兼容
- **WHEN** 调用方签名校验或权限校验不通过 THEN 拒绝并计数，上报安全事件

### US2 补充 — 失效模式
双进程状态耦合是通道失效的主要来源。通道假设任何一步都可能失败：insert 可能不返回、返回失败码、数据可能重复送达；因此接口按「**至少一次 + dedupKey 幂等去重**」设计，两侧均先落盘后传输，任一进程死亡都不丢数据。

### US3 — 实时上报
**作为** 数据平台，**我要** 事件实时上传数据中台并落仓，**以便** 支撑实时看板与监控。

**验收标准**
- **count/size/time 三维触发上报**：合并窗口 5s 到期、批满 50 条、累计 256KB（压缩后）任一满足即触发
- **令牌桶流控**：平台侧默认 1000 ev/s、桶深 1000；超出进入待报队列而非丢弃；参数可由服务端配置中心动态下发（100–2000 ev/s）
- **实时性界定**：合并窗口 ≤ 10s；端到端可见性 SLO：事件产生 → ClickHouse 可查 ≤ 60s（P95），持续 5min 超标则每分钟告警
- **WHEN** 上报失败 THEN 指数退避重试 30s/1m/5m/30m 共 4 次，失败数据回队列头，恢复后续传
- **WHEN** 网络不可用 THEN 滞留待报队列，网络恢复立即续传
- **WHEN** 服务端返回 401/403 THEN 停止上报并告警；429 → 按 `Retry-After` 退避；5xx/网络错误 → 指数退避
- **分级降级**：连续失败累计计算通道健康度，< 0.6 时降级为「仅缓存模式」：采集照常、上报暂停；恢复 ≥ 0.8 且持续 10min 后渐进放量恢复（1/4 → 1/2 → 全量，每级稳定 5min）
- **本地保护**：TTL 3 天，超期丢弃并计丢弃率；磁盘队列容量 20MB（可配），满时按「最新优先」淘汰最旧分片并计数
- **WHEN** 设备/用户行使退出权（`optOut`） THEN 立即停止采集与上报、清空内存与磁盘队列、状态持久化；`optIn` 后重新采集

### US4 — 异常与降级
**作为** 平台稳定性负责人，**我要** 通道各环节的异常都被分类处置、降级和计数，**以便** 数据完整性可审计、不因通道故障影响业务进程。

**验收标准**
- **WHEN** 单条事件压缩后 > 256KB THEN 拆分重编码；> 1MB 判定为业务异常数据，丢弃并计丢弃计数，保护通道
- **WHEN** 同一 `dedupKey` 事件 90s 窗口内重复到达 THEN 幂等去重，仅计一次（可配窗口）
- **WHEN** IPC 传输异常（`DEAD_OBJECT` / `RuntimeException` / 8s 超时） THEN 保留本地、退避重连；insert 是轻操作，超时视为服务端异常信号
- **WHEN** 业务进程被杀 THEN 事件已先落通道本地兜底库，进程重启后续传
- **WHEN** 平台进程被杀 THEN 业务进程继续采集落本地，探活重连后分批补传
- **WHEN** DataProvider 插入是轻操作（权限校验 + 单事务写入平台本地库） THEN 延迟 P95 ≤ 10ms，不构成业务进程性能瓶颈
- **WHEN** SDK 自身发生未捕获异常 THEN 拦截器捕获后隔离故障模块，业务进程不受影响；SDK 崩溃率 0（不产生业务进程新增崩溃）
- **守护进程模式（可选）**：数据平台进程被杀后由平台侧拉活机制恢复，SDK 侧只负责退避重连，不做进程保活

### US4 — 不丢数据总原则
**双进程均「先落盘后传输」**：事件先落各自进程内的 Room 队列，传输确认成功才删除；配合数据中台侧幂等写入，实现全链路「至少一次 + 幂等去重」。

## 边界情况（Edge Cases）
| # | 场景 | 处置 |
| --- | --- | --- |
| E1 | 事件属性含非法值（NaN/超长字符串） | 入队前校验：非法值剔除属性并计数；事件主体保留 |
| E2 | 服务端配置下发失败 | 沿用上次有效配置，5min 后重试拉取 |
| E3 | 设备磁盘满（< 10MB 可用） | 磁盘队列写入失败转降级内存缓冲（512KB 有界，满则丢最旧+计数），恢复后回灌 |
| E4 | 多进程并发写入 DataProvider（≥ 3 个业务进程） | Provider 内部串行化（单写线程 + 锁），插入 P95 ≤ 10ms |
| E4b | 同一进程高并发调用 track() | 内存队列加锁，单消费者批量出队 |
| E5 | 客户端时钟偏移 | 事件携带 SDK 侧时间戳 + 服务端接收时间戳双时间戳，分析侧双轨计算 |
| E6 | 重复上报（重传后服务端已收） | 服务端按 dedupKey 幂等去重（Kafka key + CH ReplacingMergeTree(session_id)）|
| E7 | 协议字段新增（minor 升级） | proto 未知字段保留；旧客户端收到新字段忽略 |
| E8 | 用户提供非法 config（非法 URL/负数批量阈值） | 初始化时校验，非法值回退默认值并计数 |
| E8b | 服务端下发非法配置 | 校验后拒绝并沿用上次有效配置 |
| E9 | 事件 ID 未知 | 收录并计数（未知点位计数上报，用于发现脏数据） |
| E10 | 队列中出现超 TTL（3 天）数据 | 上报前过滤丢弃并计数 |
| E11 | 服务端返回格式错误响应 | 截留原始响应采样存证，按 5xx 处置 |

## 功能边界（Non-Goals / Out of Scope）
- 不做 UI 埋点可视化（圈选）与 A/B 实验平台，本期只提供采集与传输能力
- 不做业务进程内的实时消费：事件只经通道进入数据平台进程，业务进程不直接上报网络
- 不做跨设备数据同步与用户画像计算，画像属于数据中台下游服务
- SDK 不做进程保活（守护拉活由平台侧自行实现），SDK 只负责退避重连
- 数据中台的离线数仓、BI 看板只作为下游消费方，其内部实现不在本规格范围
